## PR #10 (multi-select-drag-reorder) review findings

- [x] Bulk delete of multi-selected playlist tracks is still broken on Plex: `PlaylistsScreen.kt` `removeSongs()` calls `reorderPlaylist` with a shorter song-id list, which `PlexClient.kt`'s new size-equality guard (~line 760) now refuses. Fixed by having `removeSongs()` issue per-index `removeFromPlaylistAt` deletes (highest index first) instead of round-tripping through `reorderPlaylist`, so it no longer trips that guard on Plex and doesn't need the DRY reorder refactor.
- [x] `PlexClient.kt` `reorderPlaylist` (~line 786) now issues a sequential awaited PUT move request for every entry from index 1 onward, with no skip for entries already in the correct position (main's prior code skipped no-ops via `if (at != target)`). Dragging one track in a large playlist now fires hundreds of requests, and any single failure aborts the whole reorder. Fixed by tracking the running order locally as moves land and skipping any entry already directly after its wanted predecessor.
- [x] `LibraryRepository.kt` `pendingPlaylistWrites` (~line 511) tracks in-flight writes with a plain `Set<String>`, not a reference count. Two concurrent writes to the same playlist id can cause the saving indicator to disappear while a save is still in flight. Fixed with a per-id write count guarding the set updates.

Worth a visible error state once the above bugs are fixed and actually produce failures to see.
